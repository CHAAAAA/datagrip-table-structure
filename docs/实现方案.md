# DataGrip 插件实现方案：在编辑器标签页中查看 Oracle 表结构

> 目标环境：**DataGrip 2026.2.6（build DB-262.10968.148，本机已安装）**，插件依赖内置的
> Database Tools and SQL 插件（`com.intellij.database`）。
>
> 本文所有 API 签名、扩展点、行为结论均来自对**本机已安装 DataGrip 2026.2.6 的真实 jar**
> 的反编译/字节码/插件描述符核对（`javap`、`unzip -p … META-INF/plugin.xml`），
> 不是凭记忆写的；关键代码已用 DataGrip 自带 JBR 25 的 `javac` 对真实平台 jar 编译通过。

---

## 0. 结论先行

1. **DataGrip 2026.2 默认仍然是“弹窗”**：右键表 → `Modify Object…`（内部动作
   `DatabaseView.Ddl.AlterObject`，类 `com.intellij.database.actions.ddl.ModifyObjectAction`）
   走的是 `DbModifyObjectDialog`（DialogWrapper）。
2. 2026.2 已经存在一个**实验性**的“复合表编辑器”实现：一个编辑器 tab 内包含
   Data / **Structure** / DDL 三个内页（类 `com.intellij.database.editor.DatabaseCompositeTableEditor`，
   内页枚举 `EditorTab.DATA_EDITOR / STRUCTURE_EDITOR / CODE_EDITOR`），由注册表开关
   `database.editor.composite`（默认 `false`）控制：
   ```java
   // 反编译 com.intellij.database.editor.DatabaseCompositeTableEditorProviderKt
   Registry.is("database.editor.composite", false)
   ```
   **零代码备选方案**：在 DataGrip 里 `Help → Find Action → Registry…` 打开
   `database.editor.composite` 后重启，双击表即可得到带 Structure 内页的 tab。
   但它是实验特性、偏“编辑表结构”（Modify Object 面板），且没有第三方扩展点可以往里加页签
   （已核对 `com.intellij.database` 插件声明的全部 87 个扩展点，没有任何 tab/page/dataEditor 扩展点）。
3. 因此要做一个**稳定、只读、一屏展示“列 + 索引 + 主键/唯一 + 外键 + 总体信息”的查看器**，
   正确做法是**自建普通编辑器 tab**：`FileEditorProvider` + 自定义 `FileType` +
   `LightVirtualFile` + 一个纯 Swing 面板。这也是本方案的核心。
4. 技术栈只需两步：**DataGrip 已内省好的数据库模型（`com.intellij.database` 的 `Das*` API）**
   取数，**标准 IntelliJ Platform 编辑器 API** 展示。**v1 不需要任何 JDBC 查询**。

## 1. 需求拆解与验收标准

| # | 需求 | 实现要点 | 验收 |
|---|------|----------|------|
| 1 | 不用弹窗，用 **tab 页** | 注册 `FileEditorProvider`，`FileEditorManager.openFile(...)` 打开普通编辑器 tab | 打开后出现在编辑器区域 tab 栏，可拖动/拆分/固定，与 .sql 文件 tab 同级 |
| 2 | 以 **table 模式**显示字段、注释、长度等 | 内页 `JBTable`（只读、可排序）：列名/类型/长度/精度/标度/非空/默认值/主键/外键/自增/计算列/注释 | 表格列齐全、可排序、可复制单元格文本 |
| 3 | 显示表的**总体信息**：表名、索引、主键约束等 | 顶部概要区（表名、schema、注释、数据源、DBMS 版本、各类对象数量）+ 内页分别展示索引/约束/外键 | 一屏内看到全部总体信息与明细 |
| 4 | 针对 **Oracle** | 依据 `Dbms.isOracle()` 做提示/能力适配；Oracle 类型显示（`VARCHAR2(50 CHAR)`、`NUMBER(10,2)` 等） | 类型/长度展示与原表 DDL 一致 |
| 5 | 非只读需求/稳定性 | 全部只读；加载在后台读锁内完成，EDT 只渲染 | 打开大 schema 的表不卡 UI |
| 6 | 数据及时性 | 监听 `DbPsiFacade.TOPIC` + 手动刷新按钮 | 数据源 Refresh 后 tab 自动更新 |

## 2. 方案对比与选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. 自建编辑器 tab（推荐）** | `FileType` + `LightVirtualFile` + `FileEditorProvider` + `FileEditor`（Swing 面板） | 完全可控；只读轻量；不依赖实验开关；tab 行为与原生一致；可自定义 UI | 需自己实现数据读取与 UI；`LightVirtualFile` 重启后不恢复 | ✅ v1 采用 |
| B. 复用内置实验复合编辑器 | 引导用户打开 `database.editor.composite`，用内置 Structure 内页 | 零代码 | 实验特性、默认关闭；Structure 是“编辑表结构”面板；无法注入自定义页；不受支持 | 作为“零成本备选”在文档中说明 |
| C. 在数据编辑器里加内页 | 期望扩展点往 Table data editor 注入 tab | 最贴合直觉 | **不存在这样的扩展点**（已核对全部扩展点） | ❌ 不可行 |
| D. ToolWindow 内嵌 tabs | 注册 ToolWindow，窗口内放多个 tab | 实现简单 | 不是“编辑器 tab”，不能与 SQL 文件并排/拆分，用户明确否定了非 tab 形态（虽非弹窗） | 仅作兜底 |
| E. 直接 JDBC 查询数据字典 | 用连接执行 `ALL_TAB_COLUMNS` 等 | 信息最全（表空间/分区/行数/DDL） | 需拿连接、处理权限/方言；与 DataGrip 模型可能不一致；实现成本高 | v2 增强时再引入（见 §9.3） |

> 说明：方案 A 的“重启后 tab 不自动恢复”是 `LightVirtualFile` 的既定行为（其内部 VFS 协议为
> `mock`，未注册到 `VirtualFileManager`，重启后无法按 URL 找回）。如需恢复能力，可升级为
> “自定义 `VirtualFileSystem` + `DummyCachingFileSystem`”，约 +150~200 行，且只替换虚拟文件类
> （见 §8.4）。v1 建议不做：DB 结构 tab 开机自动恢复未必是好体验，且会依赖数据源连接状态。

## 4. 工程与构建

### 4.1 工具链（重要）

| 项 | 值 | 说明 |
|----|----|------|
| IntelliJ Platform 目标 | **DataGrip 2026.2.6** | 本机已安装；也可用 `create(IntelliJPlatformType.DataGrip, "2026.2.6"){ useInstaller = true }` 下载 |
| 构建工具 | Gradle **9.8.2** + IntelliJ Platform Gradle Plugin **2.19.0** | 2026.9 时的最新稳定版 |
| JDK | **25**（DataGrip 自带 JBR 25.0.4 即可） | 2026.2 平台 class file **major 69 = Java 25**；JDK 21 的 `javac` 无法编译（JDK 21 的 `javap` 也只能读签名，不能编译） |
| 数据库插件依赖 | `bundledPlugin("com.intellij.database")` | DataGrip / IDEA Ultimate 内置；`plugin.xml` 中 `<depends>com.intellij.database</depends>` |
| 语言 | Java 21+ 语法（骨架用 Java 25 编译） | 无需 Kotlin（平台类可用 Java 直接调用） |

> 实测：`/Applications/DataGrip.app/Contents/jbr/Contents/Home/bin/javac -version` → 25.0.4；
> `DasUtil.class` 的 `major version = 69`。

构建配置的 5 个已验证注意点：

1. `local(...)` 必须指向 **`DataGrip.app/Contents`**（Gradle 插件用 `ProductInfoPathResolver` 只尝试
   `<path>/product-info.json` 与 `<path>/Resources/product-info.json`，macOS bundle 的真实文件在
   `Contents/Resources/` 下）；
2. DataGrip 只有 installer 发行版（`IntelliJPlatformType.DataGrip` 的 `maven == null`），
   因此在线模式用 `datagrip("2026.2.6")`（默认 `useInstaller = true`），不要设 `useInstaller = false`；
3. 内置数据库插件的真实 id 就是 **`com.intellij.database`**（来自
   `DatabaseTools/lib/database-plugin.jar!/META-INF/plugin.xml`，版本 `262.10968.148`）；
4. 插件 2.x 要求 Gradle ≥ 9.0.0；Java 25 需要 Gradle ≥ 9.1.0（本方案用 9.8.2）；
5. 平台 Gradle 插件会自动按目标平台应用 Java toolchain 约定（262 → Java 25），因此 `java { toolchain }`
   是冗余但安全的写法；**不要**再设置 `options.release`（见 intellij-platform-gradle-plugin issue #1772）。

### 4.3 `src/main/resources/META-INF/plugin.xml`

```xml
<idea-plugin>
    <id>com.example.tablestructure</id>
    <name>Table Structure Viewer</name>
    <version>0.1.0</version>
    <vendor>example</vendor>

    <description>在编辑器标签页中以只读表格方式查看表结构（列/索引/约束/外键）。</description>

    <idea-version since-build="262" until-build="262.*"/>

    <depends>com.intellij.modules.platform</depends>
    <depends>com.intellij.database</depends>

    <extensions defaultExtensionNs="com.intellij">
        <fileType name="DataGripTableStructure"
                  implementationClass="com.example.tablestructure.editor.TableStructureFileType"
                  fieldName="INSTANCE"/>       <!-- 注意：不要写 extensions=，避免劫持真实文件 -->
        <fileEditorProvider implementation="com.example.tablestructure.editor.TableStructureEditorProvider"/>
    </extensions>

    <actions>
        <action id="TableStructure.OpenAction"
                class="com.example.tablestructure.action.OpenTableStructureAction"
                text="查看表结构">
            <add-to-group group-id="DatabaseViewPopupMenu" anchor="first"/>
            <keyboard-shortcut keymap="$default" first-keystroke="control alt shift S"/>
        </action>
    </actions>
</idea-plugin>
```

要点（均已核实）：

* `DatabaseViewPopupMenu` 是 DataGrip 对象树右键菜单的**静态组 id**（定义在
  `intellij.database.impl.xml`，`<group id="DatabaseViewPopupMenu">`）。
  其他可用组：`DatabaseViewToolbar`、`DatabaseView.Tools`、`Database.EditorTabPopupMenu`、
  `EditorPopupMenu`、`Console.TableResult.*`。
* `<fileType>` 必须提供 `fieldName="INSTANCE"`（平台通过 `FileTypeBean` 反射取实例）。
* `<fileEditorProvider>` 只读取 `id` / `fileType` / `isDocumentRequired` 等属性；**没有** `order` 属性，
  编辑器顺序由 `FileEditorPolicy`（`HIDE_DEFAULT_EDITOR` 等）+ `WeighedFileEditorProvider.getWeight()`
  决定。

## 5. 关键 API 清单（对照本机 2026.2.6 验证）

### 5.1 选中对象 → 表

| 用途 | API | 说明 |
|------|-----|------|
| 对象树/控制台上下文中的 DB 对象 | `com.intellij.database.DatabaseDataKeysCore.DB_EDITOR_OBJECT`（`DataKey<DbElement>`） | core.impl jar；内部 API，升级需回归 |
| 对象树选中元素 | `CommonDataKeys.PSI_ELEMENT`（`DataKey<PsiElement>`） | **已核实** `DatabaseViewPanel.uiDataSnapshot` 会惰性提供该 key（`DbNodeDescriptor.getPsiElement(...)`），值即 `DbElement` |
| 多选 | `PlatformCoreDataKeys.PSI_ELEMENT_ARRAY` | 取第一个 `DbTable` |
| 从编辑器对象拿表 | `DatabaseDataKeysCore.DATABASE_EDITOR_OBJECT`（BasicElement 模型）或 `DB_EDITOR_OBJECT` | 控制台/数据编辑器上下文 |

### 5.2 表模型（`com.intellij.database.model.*`、`util.DasUtil`）

```java
DbTable dbTable = ...;                       // com.intellij.database.psi.DbTable extends DbElement, PsiTable
DasTable table = dbTable.getDasObject();     // 数据库模型对象
DbDataSource ds = dbTable.getDataSource();   // 数据源（DasDataSource）
Dbms dbms = ds.getDbms();                    // Dbms.ORACLE 判断：dbms.isOracle()
NameVersion ver = ds.getDatabaseVersion();   // ver.version

// 列
JBIterable<? extends DasColumn> columns = DasUtil.getColumns(table);
// 列属性：getName() / getPosition() / getDasType()（→ toDataType()）/ isNotNull() / getDefault()
//        / getComment() / DasUtil.isPrimary(c) / isForeign(c) / isAutoGenerated(c) / isComputed(c)

// 索引
JBIterable<? extends DasIndex> indexes = DasUtil.getIndices(table);
// DasIndex: getName() / isUnique() / isFunctionBased() / getColumnsRef()（MultiRef，names() 取列名）
//           / getColumnSorting(name)（ASCENDING/DESCENDING/NONE）

// 主键 / 唯一约束
JBIterable<? extends DasTableKey> keys = DasUtil.getTableKeys(table);  // DasTableKey.isPrimary()
DasTableKey pk = DasUtil.getPrimaryKey(table);

// 外键
JBIterable<? extends DasForeignKey> fks = DasUtil.getForeignKeys(table);
// DasForeignKey: getRefTableName()/getRefTableSchema()/getRefColumns()/getDeleteRule()/getUpdateRule()/getDeferrability()

// 名称/schema/catalog/注释/对象类型
DasUtil.getSchema(table); DasUtil.getCatalog(table);
table.getName(); table.getComment(); table.getKind().getPresentableName();
table.isTemporary(); table.isSystem();
```

`MultiRef` 取列名：

```java
for (String name : multiRef.names()) { ... }   // 也提供 resolveObjects()
```

`DataType`（列类型/长度）：

```java
DasType dasType = column.getDasType();
DataType type = dasType.toDataType();   // 注意：DasTypedObject.getDataType() 在 2026.2 标了 @Deprecated(forRemoval)
type.typeName;          // "VARCHAR2"
type.getSpecification();// "VARCHAR2(50 CHAR)" —— 直接用于“类型”列展示
type.getLength();       // 50
type.getPrecision();    // NUMBER(10,2) → 10
type.getScale();        // → 2
type.sizeUnit;          // LengthUnit.BYTE / CHAR（可为 null）
```

> 已核实：Oracle 内省会把**表/列注释**读进模型（`intellij.database.dialects.oracle.jar` 中
> `OraIntroQueries$OneComment` 映射 `table_name / column_name / comments`），所以
> `table.getComment()` / `column.getComment()` 可用，**不需要**自己查 `ALL_TAB_COMMENTS`。

### 5.3 编辑器 tab

| 用途 | API | 备注 |
|------|-----|------|
| 打开/复用 tab | `FileEditorManager.getInstance(project).openFile(virtualFile, true)` | 以 **VirtualFile 实例身份**去重，所以需要 project service 缓存 |
| 编辑器壳 | `FileEditorProvider`（`createEditor(Project, VirtualFile)`、`getEditorTypeId()`、`getPolicy()`） | **没有** `createFileEditor` 方法（那是 `AsyncFileEditorProvider` 的 Kotlin suspend 方法） |
| 编辑器内容 | `FileEditor`：`getComponent/getPreferredFocusedComponent/getName/getFile/setState/isModified/isValid/add/removePropertyChangeListener/dispose` | `getFile()` 必须覆盖（默认实现会记 `PluginException`）；`FileEditor` 在 2026.2 还要求 `UserDataHolder` 的方法 → 直接 `extends UserDataHolderBase` |
| 文件类型 | 自定义 `FileType`（`getName/getDescription/getDefaultExtension/getIcon/isBinary`） | `isBinary()=true` 避免平台创建 Document；图标用 `AllIcons.Nodes.DataTables` |
| 虚拟文件 | `com.intellij.testFramework.LightVirtualFile` | 内存文件，`(name, fileType, "")`；内部 VFS 协议 `mock`，**重启后不能恢复** |
| 策略 | `FileEditorPolicy.HIDE_DEFAULT_EDITOR` | 必须同时实现 `DumbAware`，否则平台 `checkPolicy()` 记 `PluginException` |

### 5.4 异步/线程

```java
ReadAction.nonBlocking((Callable<TableStructure>) () -> TableStructureLoader.load(table))
    .inSmartMode(project)
    .expireWith(this)                          // FileEditor 是 Disposable
    .submit(AppExecutorUtil.getAppExecutorService())
    .onSuccess(structure -> ApplicationManager.getApplication()
        .invokeLater(() -> panel.showStructure(structure), ModalityState.any()))
    .onError(error -> ...);
```

* 模型/PSI 只能在读锁内访问；UI 只能在 EDT 更新。
* 2026.2 中 `ReadAction.compute(...)` 已标记 **deprecated**（只是 `computeBlocking` 的包装），
  同步场景改用 `ReadAction.computeBlocking(...)`。
* `DbPsiFacade.TOPIC`（`Topic<DbPsiFacade.Listener>`，`onChanged(DbDataSource)`）可用于
  “数据源模型变化 → 自动刷新”；用 `project.getMessageBus().connect(this).subscribe(...)` 注册。

## 6. 数据读取设计

### 6.1 数据来源：优先使用 DataGrip 模型（v1）

* 列 / 索引 / 主键唯一约束 / 外键 / 注释 / 类型长度：**全部来自 DataGrip 已内省的模型**，
  不发起 JDBC 查询；
* 前提是模型已加载：用户能在对象树看到该表 ⇒ 该 schema 已被内省；此时 columns/indices/keys
  通常在模型里（DataGrip 的内省粒度是 schema/对象集合）。
* 模型未加载 / 被清理 / 无权限时：`DasUtil.getColumns(...)` 可能返回空 → UI 显示“未加载/无数据 +
  建议刷新数据源”，刷新按钮重新读模型。

### 6.2 字段映射

| UI 列 | 数据来源 |
|-------|----------|
| `#` | `DasPositioned.getPosition()`（Oracle = COLUMN_ID） |
| 列名 | `DasNamed.getName()` |
| 类型 | `DataType.getSpecification()`（如 `NUMBER(10,2)`、`VARCHAR2(50 CHAR)`） |
| 长度 | `DataType.getLength()`（0 显示空） |
| 精度 / 标度 | `DataType.getPrecision()` / `getScale()` |
| 非空 | `DasTypedObject.isNotNull()` |
| 默认值 | `DasTypedObject.getDefault()` |
| 主键 / 外键 | `DasUtil.isPrimary(col)` / `isForeign(col)` |
| 自增 / 计算列 | `DasUtil.isAutoGenerated(col)` / `isComputed(col)` |
| 注释 | `DasObject.getComment()` |
| 索引 | 名称/唯一性/函数索引/列（`MultiRef.names()` 拼接） |
| 约束 | `DasTableKey.isPrimary()` → 类型列“主键/唯一” |
| 外键 | `DasForeignKey` 的引用表/列/规则/延迟性 |
| 总体信息 | 表名/schema/注释/数据源/DBMS 版本/对象类型/临时表/系统表/各对象数量 |

### 6.3 刷新策略

1. **首次**：编辑器构造时异步加载；
2. **手动**：面板右上角“刷新”按钮；
3. **自动**：订阅 `DbPsiFacade.TOPIC`，`onChanged(dbDataSource)` 且与当前表同数据源时重新加载
   （骨架里简化成任意数据源变化都刷新，生产实现可按 `DbDataSource.getUniqueId()` 过滤）；
4. **失效**：`SmartPsiElementPointer.getElement()` 为 null（表被删/模型卸载）→ 显示错误态并提示重开。

## 8. 编辑器 tab 生命周期

### 8.1 打开与去重

* `openFile` 以 VirtualFile 实例为 key ⇒ 用 `@Service(Service.Level.PROJECT)` 的
  `TableStructureService` 维护 `Map<TableKey, TableStructureVirtualFile>`，
  同表永远复用同一个实例（否则会开出多个重复 tab）；
* `TableKey = dataSourceUniqueId + schema + tableName`，规避多数据源同名表/不同 schema 同名表；
* 虚拟文件内部持 `SmartPsiElementPointer<DbTable>`，模型刷新后仍可重新解析到最新表对象。

### 8.2 关闭/失效

* 用户关 tab：平台 `dispose()` 编辑器 → 取消进行中的读任务、断开消息总线；
  project service 里的 VirtualFile 可保留（下次打开复用），也可在 `FileEditorManager` 关闭回调清理；
* 表被删除/重命名：smart pointer 失效 → 错误态；`invalidate(key)` + 下次打开新建实例。

### 8.3 重启恢复（v1 不做）

`LightVirtualFile` 的内部 VFS 协议是 `mock`，且**未注册**到 `VirtualFileManager`；平台保存了编辑器
状态但重启恢复时 `findFileByUrl` 解析失败，tab 被丢弃（已实测确认）。可选升级方案：

```java
// 1) 注册自定义 VFS（扩展点 com.intellij.virtualFileSystem，bean: key/implementationClass/physical）
// 2) 继承 DummyCachingFileSystem<T>，只实现 findFileByPathInner(路径 → VirtualFile)
// 3) URL 编码 "tablekey://<dataSourceId>/<schema>/<table>"
// 4) FileEditorProvider.accept 改为识别自定义 file system
// 重启后平台可按 URL 找回虚拟文件 → tab 自动恢复（约 +150~200 行；只在虚拟文件类上换实现）
```

> 建议：确认“重启后自动恢复 DB 结构 tab”是刚需再做；否则保持 v1。

### 9.1 DDL 内页

* 内置能力：`com.intellij.database.editor.DatabaseEditorHelper.loadOrGenerateDefinition(DbElement, StringBuilder)`
  可拿到 DataGrip 生成的 DDL（内部 API），用只读文本框/编辑器展示；

### 9.2 Oracle 专属深度信息（JDBC，需连接）

模型里没有的信息（表空间、分区、统计行数、`IDENTITY_COLUMN`、隐藏列等）可通过数据源连接查询：

```sql
-- 表级
SELECT t.NUM_ROWS, t.TABLESPACE_NAME, t.PARTITIONED, t.TEMPORARY, t.LAST_ANALYZED,
       c.COMMENTS
FROM ALL_TABLES t
LEFT JOIN ALL_TAB_COMMENTS c ON c.OWNER = t.OWNER AND c.TABLE_NAME = t.TABLE_NAME
WHERE t.OWNER = :owner AND t.TABLE_NAME = :table;

-- 列级（精确长度/字符语义）
SELECT column_id, column_name, data_type, data_length, char_length, char_used,
       data_precision, data_scale, nullable, data_default, identity_column, virtual_column
FROM ALL_TAB_COLUMNS
WHERE owner = :owner AND table_name = :table
ORDER BY column_id;

-- 索引
SELECT i.index_name, i.uniqueness, i.index_type, i.tablespace_name,
       ic.column_position, ic.column_name
FROM ALL_INDEXES i
JOIN ALL_IND_COLUMNS ic ON ic.index_owner = i.owner AND ic.index_name = i.index_name
WHERE i.owner = :owner AND i.table_name = :table
ORDER BY i.index_name, ic.column_position;

-- 约束（含 CHECK / 禁用状态，模型 API 不提供）
SELECT c.constraint_name, c.constraint_type, c.status, c.validated, c.search_condition,
       cc.column_name, cc.position, c.r_constraint_name
FROM ALL_CONSTRAINTS c
LEFT JOIN ALL_CONS_COLUMNS cc
  ON cc.owner = c.owner AND cc.constraint_name = c.constraint_name
WHERE c.owner = :owner AND c.table_name = :table
ORDER BY c.constraint_name, cc.position;
```

连接获取（2026.2 可用，内部 API）：`com.intellij.database.dataSource.DatabaseConnectionManager`
+ `DatabaseConnection`（`intellij.database.connectivity.jar`）；
或走 DataGrip 的 console/run API。**建议 v2 再评估**，v1 保持零 JDBC 依赖。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| `com.intellij.database.*` 是 **内部 API**，无兼容承诺 | IDE 升级可能编译/运行失败 | 固定目标版本；每版本 `verifyPlugin`；把内部 API 调用收敛到 `TableStructureLoader` + `Action` 两处适配层 |
| `LightVirtualFile` tab 重启不恢复 | 用户重启后 tab 丢失 | v1 接受；v2 用自定义 VFS（见 §8.3）实现恢复 |
| 模型未加载/无权限导致数据为空 | 用户误以为插件坏 | 空态提示 + 刷新按钮 + 文档说明（先展开/刷新数据源）；v2 可 JDBC 兜底 |
| 大 schema 模型访问慢 | 打开卡顿 | 后台读锁 + 只遍历目标表；避免全 schema 扫描；加载中 UI 有状态 |
| `DatabaseViewPopupMenu` 组在新 UI 下行为变化 | 菜单入口消失 | 同时注册 `DatabaseViewToolbar`/`Database.EditorTabPopupMenu`/快捷键；升级回归 |
| Marketplace 审核/依赖 | 无法发布/被标记 | 声明 `<depends>com.intellij.database</depends>` 与 `since-build`；用官方 Gradle 2.x + `verifyPlugin`；内部 API 用法可接受但会在 verifier 中报 `INTERNAL_API_USAGES`（自用无碍） |
| JDK 25 toolchain 缺失（CI） | 构建失败 | CI 装 JDK 25 或复用 DataGrip JBR；`org.gradle.java.installations.paths` 指向 JBR |
| Oracle 对象名大小写/引号 | 展示/匹配错误 | 用模型对象名原样展示；key 去重时保持原样（模型已处理 casing） |
| 数据源多开同名表 | 去重错误 | `TableKey` 包含 `DbDataSource.getUniqueId()` |

## 14. 为什么不用/不直接复用内置实现（补充说明）

* 内置的 `TableStructureFileEditor` 是 `DatabaseCompositeTableEditor` 的**内页**，
  `EditorTab` 枚举是 **package-private**，打开入口是内部 `OpenStructureFileDescriptor` /
  `DbNavigationUtils`，没有公开 API 可以“让第三方打开 Structure 内页并复用”；
* 该内页是 `DbModifyObjectDialogPanel`（编辑表结构）的编辑器化外壳，偏编辑；只读查看器更轻、
  可自定义列（长度/精度/注释一屏展示）；
* 平台/数据库插件**没有**允许第三方往表数据编辑器注入 tab 的扩展点（87 个扩展点逐一核对）。
